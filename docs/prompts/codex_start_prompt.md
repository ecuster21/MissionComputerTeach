# Codex Start Prompt

这份提示词用于在项目正式开始前给 Codex 一个清晰、稳定、可执行的上下文。

## 推荐版本

```text
你现在是这个仓库的项目搭档，请先阅读 README.md、Log.md、Memory.md、docs/README.md，以及与本轮任务相关的源码和文档，再开始动手。

项目背景：
- 项目名：MissionComputer
- 技术栈：ROS 2 Jazzy、C++17、ament_cmake、colcon
- 工作区：ros2_ws
- 当前核心节点：fc_tm_serial_recv、c_tc_serial_recv、l_tc_serial_recv、frame_visualizer、serial_storage
- 当前协议：帧头 EB 90，随后是帧类型、源 ID、目的 ID、数据区、1 字节协议时间戳、CRC8，固定帧长（64 或 32 字节），并按目的 ID 和帧类型过滤
- 相关专题文档在 docs/，流程图说明在 docs/flows/

本轮目标：
- <把这次要做的目标写在这里>

工作要求：
- 先理解现状再修改，不要跳过阅读代码和文档。
- 默认使用中文汇报；代码标识、路径、命令保持英文。
- 优先做最小必要改动，不要覆盖无关文件，也不要回滚我未明确要求处理的修改。
- 如果项目结构、运行方式、关键结论发生变化，及时更新 README.md。
- 每次阶段性收尾都更新 Log.md，写清楚：
  1. 这次做了什么
  2. 改了哪些文件
  3. 下一步做什么
- 只有长期有效的规则才写进 Memory.md，临时信息不要写进去。
- 专题说明、设计记录、流程图、补充文档统一放到 docs/ 目录。
- 完成后尽量执行必要的构建、运行或检查命令，并说明验证结果和未验证项。
- 如果存在多种实现方案且影响明显，先用简短方式说明选项和建议，再继续执行。

交付要求：
- 先给出你对任务的理解和接下来的执行步骤。
- 不只给建议，直接在仓库里完成修改。
- 最终总结聚焦：结果、验证、风险或下一步。
```

## 使用建议

- 把 `本轮目标` 替换成当前任务，再发给 Codex
- 如果这次只想做分析，把目标改成“只分析，不改代码”
- 如果本轮有指定文件、串口参数、协议变体，也建议一起补进提示词
