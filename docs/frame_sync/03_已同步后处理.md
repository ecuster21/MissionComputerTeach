# 已同步后的处理

这张图描述 `is_synced == true` 后的主处理逻辑。

```mermaid
flowchart TB
    A[已经进入同步状态] --> B{bytes_in_buffer == 0 ?}

    B -- 是 --> C[调用 read_exact 直接读满 64 字节]
    C --> D{frame.has_valid_header ?}
    D -- 否 --> E[打印校验失败日志]
    D -- 是 --> F{frame.validate_crc16 ?}
    F -- 否 --> E
    F -- 是 --> G[调用 publish_frame]
    G --> H[继续下一轮同步帧读取]

    E --> I[把这 64 字节复制回缓冲区]
    I --> J[bytes_in_buffer = FRAME_LENGTH]
    J --> K[is_synced = false]
    K --> L[返回外层循环等待重同步]

    B -- 否 --> M{bytes_in_buffer < FRAME_LENGTH ?}
    M -- 是 --> N[继续从串口补读到缓冲区尾部]
    N --> O{补读后是否已有 64 字节?}
    O -- 否 --> L2[本轮先返回外层循环]
    O -- 是 --> P[复制缓冲区前 64 字节到 frame]
    M -- 否 --> P[复制缓冲区前 64 字节到 frame]

    P --> Q{frame.has_valid_header ?}
    Q -- 否 --> R[打印校验失败日志]
    Q -- 是 --> S{frame.validate_crc16 ?}
    S -- 否 --> R
    S -- 是 --> T[调用 publish_frame]
    T --> U[consume_bytes FRAME_LENGTH]
    U --> B

    R --> V[仅丢弃缓冲区最前面的 1 字节]
    V --> W[再次调用 try_find_sync]
    W --> X{是否重新找到同步点?}
    X -- 是 --> Y[丢弃新同步点前的无效字节]
    Y --> B
    X -- 否 --> Z[is_synced = false]
    Z --> L
```

## 当前实现的两个已同步分支

- 分支 1：用户态缓冲为空  
  这时直接调用 `read_exact()` 精确读取 `64` 字节

- 分支 2：用户态缓冲里还有历史残留字节  
  先把缓冲区里的数据补齐并消化完，再决定是否继续保持同步

## 当前校验逻辑

每一帧都会检查两层内容：

- 帧头是否为 `EB 90`
- CRC16 是否与当前配置的 `crc16_variant` 和 `crc16_big_endian` 一致

这也是为什么即使已经同步，仍然不能盲信后续每帧都一定正确。
