# 已同步后的处理

这张图描述 `is_synced == true` 后的主处理逻辑。

```mermaid
flowchart TB
    A[已经进入同步状态] --> B{bytes_in_buffer >= FRAME_LENGTH ?}
    B -- 否 --> C[当前数据不足 1 帧<br/>返回外层循环继续读串口]
    B -- 是 --> D[复制缓冲区前 64 字节到 frame]

    D --> E{frame.has_valid_header ?}
    E -- 否 --> F[本帧头不正确]
    E -- 是 --> G{frame.validate_checksum ?}
    G -- 否 --> H[CRC 校验失败]
    G -- 是 --> I[调用 publish_frame]

    I --> J[将原始帧复制到 SyncedFrame.msg]
    J --> K[写入 timestamp_ns]
    K --> L[通过 frame_publisher 发布]
    L --> M[丢弃这 1 帧数据<br/>consume_bytes FRAME_LENGTH]
    M --> B

    F --> N[转入重同步逻辑]
    H --> N
```

## 这里做了什么

- 一旦同步建立，程序就不再按字节扫描
- 而是直接按固定帧长 `64` 字节切帧
- 每一帧都做两层检查：
  - 帧头是否为 `EB 90`
  - CRC 是否等于前 `63` 字节累加和

## 为什么同步后还要再次检查

因为串口流中仍可能出现：

- 丢字节
- 插入干扰字节
- 设备重启后半帧数据

所以即使已经同步，也不能盲信每一帧都一定正确。
