# 寻找同步点

这张图对应当前 `try_find_sync()` 的实现。

```mermaid
flowchart TB
    A[进入 try_find_sync] --> B{当前有效字节数<br/>是否小于 FRAME_LENGTH + 2 ?}
    B -- 是 --> C[offset = 0<br/>返回 false]
    B -- 否 --> D[从 i = 0 开始扫描]

    D --> E{i + FRAME_LENGTH + 1 < bytes_in_buffer ?}
    E -- 否 --> F[整段扫描结束<br/>仍未找到同步点]
    F --> G[offset = 0<br/>返回 false]

    E -- 是 --> H{buffer[i] == EB<br/>且 buffer[i + 1] == 90 ?}
    H -- 否 --> I[i = i + 1]
    I --> E

    H -- 是 --> J{buffer[i + FRAME_LENGTH] == EB<br/>且 buffer[i + FRAME_LENGTH + 1] == 90 ?}
    J -- 否 --> I

    J -- 是 --> K[确认找到两个相隔一整帧的连续帧头]
    K --> L[offset = i]
    L --> M[返回 true]
```

## 这个函数当前只做两件事

- 判断当前有效缓冲区里是否存在可信同步点
- 如果存在，通过 `offset` 告诉调用者“同步点在缓冲区里的哪个位置”

## 它当前不做什么

- 不负责移动缓冲区数据
- 不负责裁剪尾部旧数据
- 不负责进入同步状态

这些动作都在调用方 `receive_data()` 里完成。

## 为什么要看两个帧头

如果只看到一个 `EB 90`：

- 它可能只是数据区里的偶然字节组合
- 还不能确认当前位置真的是一帧开头

再检查 `当前位置 + 64` 是否还是 `EB 90`，误判概率会小很多。
