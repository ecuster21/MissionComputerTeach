# 寻找同步点

这张图对应 `try_find_sync()`。

```mermaid
flowchart TB
    A[进入 try_find_sync] --> B{当前缓冲区字节数<br/>是否小于 FRAME_LENGTH + 2 ?}
    B -- 是 --> C[数据不够形成连续两个帧头判断<br/>返回 false]
    B -- 否 --> D[从 i = 0 开始扫描]

    D --> E{i + FRAME_LENGTH + 1 < bytes_in_buffer ?}
    E -- 否 --> M[整段扫描结束<br/>仍未找到同步点]
    E -- 是 --> F{buffer[i] == EB<br/>且 buffer[i + 1] == 90 ?}

    F -- 否 --> G[i = i + 1]
    G --> E

    F -- 是 --> H{buffer[i + FRAME_LENGTH] == EB<br/>且 buffer[i + FRAME_LENGTH + 1] == 90 ?}
    H -- 否 --> G

    H -- 是 --> I[确认找到两个相隔一整帧的连续帧头]
    I --> J[丢弃 i 之前的所有无效字节]
    J --> K[返回 true]

    M --> N[keep_bytes = min bytes_in_buffer, FRAME_LENGTH + 1]
    N --> O{是否需要裁剪旧数据?}
    O -- 否 --> P[直接返回 false]
    O -- 是 --> Q[只保留缓冲区最后 keep_bytes 个字节]
    Q --> P
```

## 为什么要看两个帧头

假设某个位置 `i` 恰好是数据区里的偶然字节 `EB 90`：

- 如果只看一个帧头，很容易误判
- 现在还要检查 `i + 64` 的位置是不是下一帧帧头
- 只有两个位置都匹配，才说明这个 `i` 大概率是真正帧起点

## 这个函数的输出含义

- 返回 `true`
  说明当前缓冲区开头已经对齐到一个可信的帧起点
- 返回 `false`
  说明还不能确定同步点，需要继续读串口数据
