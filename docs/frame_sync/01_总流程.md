# 帧同步总流程

这张图描述当前 `serial_receiver.cpp` 中 `receive_data()` 的主流程。

```mermaid
flowchart TB
    A[启动 serial_receiver 节点] --> B[声明参数<br/>port / baud_rate / timeout_ms / crc16_variant / crc16_big_endian / topic]
    B --> C[创建 frame_publisher]
    C --> D[尝试初始化串口]
    D --> E[启动接收线程 receive_data]

    E --> F{ROS 仍在运行<br/>且 stop_requested 为 false?}
    F -- 否 --> Z[线程退出]
    F -- 是 --> G{串口已打开?}

    G -- 否 --> H[调用 initialize_serial]
    H --> I{打开成功?}
    I -- 否 --> J[等待 500ms]
    J --> F
    I -- 是 --> K[清空状态<br/>bytes_in_buffer = 0<br/>is_synced = false]
    K --> L[继续接收]

    G -- 是 --> L{当前是否已同步?}

    L -- 否 --> M{搜索缓冲区是否已满?}
    M -- 是 --> N[丢弃最旧的一帧长度数据<br/>consume_bytes FRAME_LENGTH]
    M -- 否 --> O[直接读取]
    N --> O[从串口读取新字节到缓冲区尾部]
    O --> P{读串口是否异常?}
    P -- 是 --> Q[记录告警并关闭串口]
    Q --> R[清空状态并等待 200ms]
    R --> F
    P -- 否 --> S{本次是否读到 0 字节?}
    S -- 是 --> T[等待 5ms]
    T --> F
    S -- 否 --> U[bytes_in_buffer += bytes_read]
    U --> V[调用 try_find_sync]
    V --> W{是否找到同步点?}
    W -- 否 --> F
    W -- 是 --> X[丢弃同步点之前的无效字节<br/>consume_bytes offset]
    X --> Y[is_synced = true]
    Y --> AA[进入已同步处理]

    L -- 是 --> AA{bytes_in_buffer == 0 ?}
    AA -- 是 --> AB[调用 read_exact 精确读取 64 字节]
    AB --> AC{帧头正确且 CRC16 正确?}
    AC -- 是 --> AD[调用 publish_frame]
    AD --> F
    AC -- 否 --> AE[打印 CRC 诊断日志]
    AE --> AF[把这 64 字节复制回缓冲区]
    AF --> AG[bytes_in_buffer = FRAME_LENGTH<br/>is_synced = false]
    AG --> F

    AA -- 否 --> AH{bytes_in_buffer < FRAME_LENGTH ?}
    AH -- 是 --> AI[继续补读，直到至少凑满一帧<br/>或本轮只读到 0 字节]
    AI --> AJ{现在是否已有 64 字节?}
    AJ -- 否 --> F
    AJ -- 是 --> AK[复制缓冲区前 64 字节到 frame]
    AH -- 否 --> AK[复制缓冲区前 64 字节到 frame]

    AK --> AL{帧头正确且 CRC16 正确?}
    AL -- 是 --> AM[调用 publish_frame]
    AM --> AN[移除这 1 帧数据<br/>consume_bytes FRAME_LENGTH]
    AN --> AA
    AL -- 否 --> AO[打印 CRC 诊断日志]
    AO --> AP[只丢弃 1 字节]
    AP --> AQ[再次调用 try_find_sync]
    AQ --> AR{是否重新找到同步点?}
    AR -- 是 --> AS[丢弃新同步点前的无效字节]
    AS --> AA
    AR -- 否 --> AT[is_synced = false]
    AT --> F
```

## 当前实现的关键点

- 初始同步不是只看一个 `EB 90`，而是必须找到两个相隔 `FRAME_LENGTH` 的帧头
- 同步建立后，会优先把用户态缓冲区里已经读到的残留数据处理完
- 只有当 `bytes_in_buffer == 0` 时，才切换到 `read_exact(..., 64)` 的固定帧长读取模式
- 校验失败时会输出详细 CRC 诊断日志，帮助判断 CRC16 变体和字节序是否配置正确
